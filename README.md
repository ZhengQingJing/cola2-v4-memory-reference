# 扩散持续神经记忆

**项目状态：尚未完成 · 源码仅供参考**  
最近一次完成训练和评估的原型为 **Cola2 v4（2026-11-12）**。

项目研究如何为小模型接入持续神经记忆，让模型从自身经历中学习，在清空上下文和重启进程后，利用学到的关系、规则与技能处理新情境。扩散是核心机制。最终验收是模型通过 Minecraft MCP 在生存模式下通关，目前尚未达成。

## Cola2 v4 的实际进展

- 在冻结的 Cola2 原生扩散网络中加入共享适配参数和各经历流独立的记忆参数。共享阶段完成 160 次更新，随后冻结共享参数，让两个新的合成经历流从同一记忆初态开始，共完成 256 次个人更新。同一流在加入新事件时延续之前的记忆状态。
- 在新进程中，仅用公开题面和已保存参数完成 520 条独立主读出。采用方向约束时，已见题生成潜变量与目标的正文余弦相似度由 MSE 组的 **0.100** 提高到 **0.155**，同时减轻了潜变量幅度收缩。
- 四组对照中，接触过相应经历的 **384 条回答里有 0 条恢复了完整关系**。已见关系、条件迁移和角色交接绑定均未通过预设标准。旧关系在引入新事件前尚未完整掌握，旧知识保持率因此无法计算。
- 辅助诊断中，四条真实观察的编码均可正确解码。给生成的潜变量提供正确跨度后，完整关系仍未恢复。后续需分别定位经历写入、按线索扩散恢复和解码接口的损失。

## 当前设计与待验证能力

11 月 13 日起暂停新增模型实验，当前聚焦架构设计。目标是让实际问题与模型的思考提供召回线索，由扩散从零碎经历中重建主要事件与因果关系，形成服务于后续预测和行动的浓缩表征。

完整的思考与召回循环、选择性事件缓冲、长期规律巩固仍待实现。后续需要分别验证新经历的跨进程回忆、角色重绑定、新情境中的规则与技能迁移，以及持续学习新经历后对旧知识的保留。

## 源码与读出流程

- [Cola2 v4 主实现](scripts/user_memory_cola_v4_20261112.py) 包含共享适配训练、独立记忆更新、跨进程读出和后置评分。
- [跨度辅助诊断](scripts/user_memory_cola_v4_span_diagnostic_20261112.py) 在正式读出与评分完成后，比较已生成潜变量、真实跨度和真实观察编码。
- [运行记录工具](scripts/phase1_common.py) 管理运行范围、来源哈希和累计实验预算。归档版以当前检出目录为工作路径边界。

原实验使用 Linux CUDA、PyTorch `2.10.0+cu126` 和 Transformers `4.51.3`。归档提供本项目的三份源码。模型与上游实现由读者从 [ByteDance-Seed/Cola2](https://huggingface.co/ByteDance-Seed/Cola2) 按原实验 revision `db876b905cf719b60da33c12a75021ac111f7a67` 单独获取，适用各自条款。可先通过以下命令查看入口和参数。

```sh
python -B scripts/user_memory_cola_v4_20261112.py --help
python -B scripts/user_memory_cola_v4_span_diagnostic_20261112.py --help
```

核对实现时，可把固定 revision 的模型和源码放在检出目录下的 `models/cola2/`，将 `--model` 和 `--source-code` 指向该目录。模型读取已下载的本地代码和权重，要求 `HF_HUB_OFFLINE=1`，以及命令入口列出的缓存与临时目录变量均位于检出目录内。训练与读出阶段使用分离的 JSON 输入。

- 经历文件以 `streams` 保存各流的 `id` 与 `episodes`。每条经历包含 `id`、`stage`、`task`、`action`、`feedback` 和由 `role`、`content` 组成的 `turns`。共享实验使用四条各含十次观察的流，个人实验使用 A、B 两条各含四次旧经历和一次新事件的流。
- 正式读出文件以 `cues` 保存 `id`、`split`、`task` 和 `action`，开发和确认题面分别为十条与八条。`score` 在 520 条正式读出全部结束后才读取单独的 `cases` 评分文件。

原始实验数据、回答、日志与检查点保存在内部。以上数字来自已完成的原实验。读者可以用自行构造的输入理解流程，复现原成绩需要原始材料。
